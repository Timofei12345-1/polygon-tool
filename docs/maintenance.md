# Регламент технического обслуживания

Документ описывает регулярные работы по поддержанию polygon-tool и его данных в рабочем состоянии.

## 1. Роли

| Роль | Ответственность |
|---|---|
| Администратор | Выполняет плановые работы, ведёт журнал (раздел 6) |
| Разработчик | Обновляет код и зависимости, выпускает релизы, разбирает инциденты |

## 2. Плановые работы

| Периодичность | Работа | Команда / действие |
|---|---|---|
| Ежедневно | Автоматическая резервная копия хранилища | `python -m polygon_tool backup` (по расписанию, см. раздел 3) |
| Еженедельно | Проверка целостности всех копий | `python -m polygon_tool verify` — код возврата 0 |
| Еженедельно | Контроль свободного места и числа копий в `backups/` | `python -m polygon_tool list-backups` |
| Ежемесячно | Тестовое восстановление в отдельный каталог | раздел 4 |
| Ежемесячно | Прогон автотестов | `python -m pytest -v` (или `python -m unittest discover -s tests`) |
| Ежеквартально | Обновление Python и dev-зависимостей, повторный прогон тестов | `pip install -U -r requirements.txt` |
| Перед релизом | Полный прогон тестов, обновление `docs/test-cases.md`, `README.*`, тега версии | `docs/GIT.md` |
| Ежегодно | Пересмотр ТЗ и регламента | — |

Количество хранимых копий задаётся параметром `--keep` (по умолчанию 10). При ежедневном копировании
это 10 дней истории; для более длинной истории увеличьте `--keep` или копируйте каталог `backups/` во внешнее хранилище.

## 3. Автоматизация копирования

**Linux / macOS (cron):**
```
0 2 * * * cd /opt/polygon-tool && /usr/bin/python3 -m polygon_tool backup --keep 30 >> backup.log 2>&1
```

**Windows (Планировщик заданий):** действие «Запуск программы»: `python`, аргументы `-m polygon_tool backup --keep 30`,
рабочая папка — каталог проекта; запуск ежедневно.

Хранилище и копии держите вне репозитория (они исключены через `.gitignore`) и копируйте на отдельный носитель
(правило 3-2-1: три копии, два типа носителей, одна — вне площадки).

## 4. Процедура тестового восстановления

1. Создать каталог для проверки: `mkdir restore-test`.
2. Выполнить `python -m polygon_tool restore --file backups/<копия>.json --data-file restore-test/points.json --backup-dir restore-test/bk`.
3. Убедиться, что команда завершилась кодом 0, а `python -m polygon_tool calc -i restore-test/points.json` даёт ожидаемый результат.
4. Удалить `restore-test`, отметить результат в журнале.

## 5. Действия при сбоях

| Ситуация | Действия |
|---|---|
| `verify` сообщает о повреждённой копии | Не использовать её; восстановиться из более ранней; найти причину (диск, права, внешнее вмешательство); пересоздать копию |
| Хранилище повреждено или потеряно | `python -m polygon_tool restore` (самая свежая корректная копия — проверка выполняется автоматически); если она повреждена — `restore --file <более ранняя>` |
| Восстановились не те данные | Перед восстановлением программа сохраняет предыдущее состояние отдельной копией — откатитесь через `list-backups` и `restore --file` |
| Нет копий | Восстановить данные из внешнего носителя; настроить расписание (раздел 3) |
| Программа возвращает код 3 | Прочитать сообщение в stderr, проверить права на каталоги `data/` и `backups/`, свободное место |
| Ошибка расчёта (код 1) | Проверить входные данные по сообщению (номер строки, причина); примеры — в `examples/` |

## 7. Резервирование и безопасность

- Права на `data/` и `backups/` — только для пользователя, запускающего программу.
- Копии не шифруются; при хранении конфиденциальных координат шифруйте носитель или внешнее хранилище.
- Контрольная сумма защищает от случайного повреждения, но не от злонамеренной подмены (манифест лежит рядом с копией).
