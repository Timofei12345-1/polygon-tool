# Code style: форматирование кода при помощи black

## Зачем нужен единый стиль
- Код пишется один раз, а читается много раз: одинаковое оформление экономит время при чтении и ревью.
- Код пишется для людей: машине всё равно на пробелы и скобки, а человеку — нет.
- Единый стиль уменьшает количество споров на код-ревью и размер диффов.
- PEP 8 задаёт основные правила, но оставляет свободу в краевых случаях. Линтеры (flake8, pylint) только проверяют стиль, а форматировать приходится вручную.

## Что такое black
`black` — «бескомпромиссный» автоматический форматтер Python-кода. Стиль навязывается и почти не настраивается: все решения о форматировании уже приняты. Красота приносится в жертву консистентности.

Минус (по статье): иногда длинные тернарные выражения и склеенные строки читаются хуже. Решение — вручную взять такое выражение в скобки и отформатировать заново.

## Установка
```bash
pip install black
```
(в статье 2020 года закреплена бета-версия `19.10b0`; сейчас у black есть стабильные релизы, поэтому версию закреплять не нужно)

## Использование
```bash
black .                    # отформатировать весь проект
black src/polygon_tool/cli.py   # один файл
black --check --diff .     # только проверить (для CI), ничего не менять
```

## Конфигурация (pyproject.toml)
```toml
[tool.black]
line-length = 88
target-version = ["py310"]
exclude = '''
/(\.git|\.venv|build|dist|backups|data)/
'''
```

## Интеграция
- **Редактор/IDE:** включить запуск black при сохранении файла (VS Code: расширение Black Formatter + `editor.formatOnSave`; PyCharm: Settings → Tools → Black).
- **CI:** шаг `black --check .` в GitHub Actions блокирует код без форматирования.
- **flake8:** отключить правила, конфликтующие с black (например `E203`, `W503`) и выставить `max-line-length = 88`.
