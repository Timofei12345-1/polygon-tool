# Техническое задание

**Проект:** polygon-tool — расчёт периметра и площади многоугольника, резервное копирование точек координат
**Версия ТЗ:** 1.0 **Дата:** 21.10.2026

## 1. Цель и область применения

Разработать консольную программу на Python, которая по декартовым координатам вершин многоугольника
вычисляет его периметр и площадь, и подсистему резервного копирования и восстановления набора
картографических точек. Программа предназначена для расчётов в плоской декартовой системе координат
(условные единицы длины; единицы площади — квадраты этих единиц).

## 2. Термины

| Термин | Значение |
|---|---|
| Вершина | Точка (x, y) — пара вещественных чисел |
| Сложный многоугольник | Простой (несамопересекающийся) многоугольник, в том числе невыпуклый |
| Хранилище | JSON-файл с набором точек (по умолчанию `data/points.json`) |
| Резервная копия | Копия хранилища + манифест с контрольной суммой |

**Принятое решение.** Под «сложным» понимается невыпуклый многоугольник без самопересечений.
Площадь самопересекающегося контура неоднозначна, поэтому такие контуры отклоняются с сообщением об ошибке.
Многоугольники с отверстиями в версии 1.0 не поддерживаются.

## 3. Функциональные требования

| ID | Требование |
|---|---|
| ФТ-1 | Ввод вершин из консоли: по одной на строку в формате «x y», завершение — пустая строка или конец ввода |
| ФТ-2 | Ввод вершин из файла форматов TXT, CSV, JSON (формат определяется по расширению) |
| ФТ-3 | Вычисление периметра как суммы длин всех сторон, включая замыкающую |
| ФТ-4 | Вычисление площади по формуле Гаусса (шнуровки); результат не зависит от направления обхода |
| ФТ-5 | Проверка входных данных: ≥ 3 вершин; конечные числа; соседние вершины не совпадают; вершины не лежат на одной прямой; стороны не пересекаются и не касаются |
| ФТ-6 | Вывод результата (число вершин, периметр, площадь) в консоль |
| ФТ-7 | Вывод результата в файл (`.json` — JSON, иначе — текст) |
| ФТ-8 | Сохранение введённых точек в хранилище (ключ `--save`) |
| ФТ-9 | Создание резервной копии хранилища с манифестом (SHA-256, число точек, дата создания) |
| ФТ-10 | Проверка целостности копии по манифесту |
| ФТ-11 | Восстановление хранилища из указанной или самой свежей копии; перед заменой копия проверяется, текущее состояние сохраняется в отдельную копию |
| ФТ-12 | Ротация: хранится не более N последних копий (по умолчанию 10) |
| ФТ-13 | Просмотр списка копий |
| ФТ-14 | Понятные сообщения об ошибках без аварийного завершения с трассировкой; коды возврата по разделу 6 |

## 4. Форматы данных

**Текст / CSV.** Одна вершина в строке; разделитель — пробел, табуляция, запятая или «;».
Допустимы пустые строки, комментарии после `#` и заголовок `x,y` в первой строке. Десятичный разделитель — точка.

```
x,y
0,0
4,0
4,4
```

**JSON.** Список пар `[[0,0],[4,0],[4,4]]`, либо объект `{"points": [...]}`, либо список объектов `{"x": 0, "y": 0}`.

**Результат (JSON).** `{"vertices": 4, "perimeter": 16.0, "area": 16.0}`.

**Хранилище.** `{"points": [[x, y], ...]}` (читается программой и как входной файл).

**Резервная копия.** `backups/points_<ГГГГММДД>_<ЧЧММСС>_<мкс>.json` и `points_<...>.manifest.json`:
`format_version`, `file`, `sha256`, `points_count`, `created` (ISO 8601).

## 5. Алгоритм резервного копирования и восстановления

**Создание копии:**
1. Прочитать хранилище и проверить его структуру; повреждённые данные не копируются.
2. Записать байты хранилища в `points_<метка времени>.json` (атомарно: временный файл → `fsync` → `os.replace`).
3. Вычислить SHA-256 и записать манифест (также атомарно).
4. Ротация: если копий больше N — удалить самые старые вместе с манифестами.

**Проверка копии:** манифест существует и читается → SHA-256 файла совпадает с манифестом → структура данных корректна → число точек совпадает с манифестом.

**Восстановление:**
1. Выбрать копию (указанную или самую свежую по имени); при отсутствии копий — ошибка.
2. Проверить копию; при любой ошибке восстановление отменяется, хранилище не изменяется.
3. Прочитать содержимое копии в память.
4. Если хранилище существует — создать копию его текущего состояния (чтобы восстановление можно было откатить).
5. Атомарно заменить хранилище содержимым копии.

## 6. Обработка ошибок и коды возврата

| Код | Значение |
|---|---|
| 0 | Успешно |
| 1 | Ошибка данных: некорректный ввод, файл не найден/не читается, недопустимый многоугольник |
| 2 | Неверные аргументы командной строки |
| 3 | Ошибка хранилища, копии или восстановления (в т. ч. не пройдена проверка целостности) |

Сообщения об ошибках выводятся в stderr на русском языке и содержат причину (для файлов — номер строки).

## 7. Нефункциональные требования

| ID | Требование |
|---|---|
| НФТ-1 | Python 3.10+, только стандартная библиотека |
| НФТ-2 | Работа на Windows, Linux, macOS; кодировка файлов UTF-8 (допускается BOM) |
| НФТ-3 | Расчёт устойчив к большим абсолютным координатам (сдвиг начала координат перед шнуровкой) |
| НФТ-4 | Запись файлов данных атомарна: сбой не оставляет наполовину записанный файл |
| НФТ-5 | Время расчёта для 1000 вершин — менее 2 с |
| НФТ-6 | Весь код покрыт автоматическими тестами; ключевые сценарии описаны в `docs/test-cases.md` |

## 8. Ограничения

Плоская декартова система координат (географические широта/долгота не пересчитываются в метры);
многоугольники без отверстий; проверка самопересечений — O(n²).
