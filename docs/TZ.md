## 2. Назначение и цели разработки

### 2.1 Назначение

Программа предназначена для вычисления периметра и площади многоугольника по декартовым координатам его вершин и для сохранения и восстановления наборов картографических точек. Расчёты выполняются в плоской декартовой системе координат; единицы длины — условные, единицы площади — квадраты этих единиц.

### 2.2 Цели разработки

- получить корректные значения периметра и площади для простых и невыпуклых многоугольников;
- исключить выдачу неверных результатов для некорректных контуров (вырожденных, самопересекающихся);
- обеспечить сохранность наборов точек за счёт резервного копирования с проверкой целостности;
- обеспечить воспроизводимую проверку качества: автоматические тесты и документированные тест-кейсы.

### 2.3 Пользователи и сценарии использования

| № | Пользователь | Сценарий |
|---|---|---|
| С-1 | Пользователь | Вводит вершины в консоли, получает периметр и площадь |
| С-2 | Пользователь | Передаёт файл с вершинами (TXT, CSV, JSON), получает результат в консоли и/или файле |
| С-3 | Пользователь | Сохраняет набор точек в хранилище |
| С-4 | Администратор | Создаёт и проверяет резервные копии по расписанию |
| С-5 | Администратор | Восстанавливает хранилище после повреждения или ошибочного изменения |
| С-6 | Разработчик | Запускает автотесты, расширяет модули, выпускает релиз |

### 2.4 Принятые решения и ограничения

1. Под «сложным» понимается **невыпуклый многоугольник без самопересечений**. Площадь самопересекающегося контура неоднозначна, поэтому такие контуры отклоняются с сообщением об ошибке. Касание сторон (вершина лежит на другой стороне) считается самопересечением.
2. Многоугольники с отверстиями в версии 1.0 не поддерживаются.
3. Географические координаты (широта/долгота) не пересчитываются в метры: программа работает в плоской системе.
4. Проверка самопересечений выполняется перебором пар сторон, то есть за время O(n²).

## 3. Метод решения задачи

### 3.1 Периметр

Сумма длин всех сторон, включая замыкающую (от последней вершины к первой):

`P = Σ √((x[i+1] − x[i])² + (y[i+1] − y[i])²)`, индексы берутся по модулю n.

### 3.2 Площадь

Формула Гаусса (шнуровки):

`S = ½ · | Σ (x[i]·y[i+1] − x[i+1]·y[i]) |`.

Для устойчивости к большим абсолютным координатам перед суммированием начало координат переносится в первую вершину; суммирование выполняется точным методом (`math.fsum`). Знак суммы определяет направление обхода (положительный — против часовой стрелки), на результат он не влияет.

### 3.3 Критерии допустимости многоугольника

1. Не менее 3 вершин.
2. Координаты — конечные числа (не NaN и не бесконечность).
3. Соседние вершины, включая пару «последняя — первая», не совпадают.
4. Вершины не лежат на одной прямой.
5. Соседние стороны не накладываются друг на друга.
6. Несоседние стороны не пересекаются и не касаются.

### 4.5 Требования к техническим средствам

Персональный компьютер или сервер с ОС Windows, Linux или macOS, не менее 256 МБ оперативной памяти; свободное место на диске — не менее 100 МБ плюс объём резервных копий. Внешний носитель или сетевое хранилище — для копий вне основной площадки (см. регламент ТО).

### 4.6 Требования к информационной и программной совместимости

Входные данные: TXT, CSV, JSON (UTF-8). Результат: текст или JSON. Хранилище и манифесты: JSON. Внешние библиотеки для работы программы не требуются; для разработки используются `pytest` и `pytest-cov` (необязательно, тесты запускаются и средствами `unittest`).

### 4.7 Требования к безопасности данных

Программа не использует сеть и не передаёт данные. Доступ к хранилищу и копиям регулируется правами операционной системы. Контрольная сумма SHA-256 защищает от случайного повреждения, но не от злонамеренной подмены (манифест хранится рядом с копией).

## 5. Подсистема резервного копирования

### 5.1 Состав данных

| Объект | Расположение | Формат |
|---|---|---|
| Хранилище | `data/points.json` | `{"points": [[x, y], ...]}` |
| Резервная копия | `backups/points_<ГГГГММДД>_<ЧЧММСС>_<мкс>.json` | как у хранилища |
| Манифест | `backups/points_<...>.manifest.json` | `format_version`, `file`, `sha256`, `points_count`, `created` (ISO 8601) |

### 5.2 Создание копии

1. Прочитать хранилище и проверить структуру; повреждённые данные не копируются.
2. Записать байты хранилища в файл копии (атомарно: временный файл → `fsync` → `os.replace`).
3. Вычислить SHA-256 и записать манифест (атомарно).
4. Ротация: если копий больше N — удалить самые старые вместе с манифестами.

### 5.3 Проверка копии

Манифест существует и читается → SHA-256 файла совпадает с манифестом → структура данных корректна → число точек совпадает с манифестом. Любое нарушение — ошибка с кодом 3.

### 5.4 Восстановление

1. Выбрать копию (указанную или самую свежую по имени); при отсутствии копий — ошибка.
2. Проверить копию; при любой ошибке восстановление отменяется, хранилище не изменяется.
3. Прочитать содержимое копии в память.
4. Если хранилище существует — сохранить его текущее состояние отдельной копией (восстановление можно откатить).
5. Атомарно заменить хранилище содержимым копии.

## 9. Приложения

### Приложение А. Форматы данных

**Текст / CSV.** Одна вершина в строке; разделитель — пробел, табуляция, запятая или «;». Допустимы пустые строки, комментарии после `#` и заголовок `x,y` в первой строке. Десятичный разделитель — точка.

```
x,y
0,0
4,0
4,4
0,4
```

**JSON.** Список пар `[[0,0],[4,0],[4,4]]`, либо объект `{"points": [...]}`, либо список объектов `{"x": 0, "y": 0}`.

**Результат (JSON).** `{"vertices": 4, "perimeter": 16.0, "area": 16.0}`.

**Результат (текст).**
```
Количество вершин: 4
Периметр: 16
Площадь: 16
```
Числа округляются до 6 знаков после запятой, незначащие нули не выводятся.

### Приложение Б. Интерфейс командной строки

| Команда | Назначение |
|---|---|
| `calc [-i файл] [-o файл] [--save]` | Расчёт периметра и площади |
| `backup` | Создать резервную копию |
| `restore [--latest \| --file путь]` | Восстановить хранилище |
| `list-backups` | Список копий |
| `verify [--file путь]` | Проверка целостности копий |

Общие параметры: `--data-file` (по умолчанию `data/points.json`), `--backup-dir` (`backups`), `--keep` (10).
